# Agent Guide: anchor-ui

Admin dashboard for the Anchor OaaS platform (Vite + React + TanStack Router/Query).

## Tech Stack
- **Framework**: React 19 + Vite
- **Routing**: TanStack Router (file-based routes in `src/routes/`)
- **Data**: TanStack Query
- **UI**: shadcn/ui components + Tailwind CSS
- **API client**: generated by `@hey-api/openapi-ts` from `../apps/anchor/cmd/http/openapi.yaml`

## Key Paths
- `src/client/` — generated API types, Zod schemas, React Query hooks (**do not edit**)
- `src/pages/` — page components
- `src/routes/` — route definitions
- `src/components/` — shared components
- `openapi-ts.config.ts` — codegen config (plugins: Zod, TypeScript, TanStack Query)

## Required Skills
- Load `shadcn` before developing, adding, or significantly changing frontend components so registry search/import workflow is followed first.

## Generated Client Usage

The codegen emits three artefacts into `src/client/`:
- `types.gen.ts` — TypeScript types for all request/response shapes
- `zod.gen.ts` — Zod schemas (prefixed `z`) for every OpenAPI schema
- `@tanstack/react-query.gen` — typed query/mutation hooks

**Always use the generated Zod schemas for form validation** — never write manual validation by hand for fields that exist in the OpenAPI spec.

### Pattern: form validation with generated Zod schemas

The generated schemas mark all fields optional (OpenAPI default). Augment with `.superRefine()` to enforce required-field rules and UX-friendly messages:

```typescript
import { zMySchema } from "@/client";
import { z } from "zod";

const formSchema = zMySchema.superRefine((val, ctx) => {
  if (!val.name?.trim()) {
    ctx.addIssue({ code: z.ZodIssueCode.custom, message: "Name is required", path: ["name"] });
  }
});

// In your component:
const result = formSchema.safeParse(payload);
if (!result.success) {
  // map result.error.issues → field errors
}
```

Map snake_case API field names to camelCase form state keys when surfacing errors.

## Regenerating the Client

Run from the anchor app root:
```sh
./apps/anchor/generate_anchor.sh
```
Then `pnpm generate` inside `anchor-ui` regenerates `src/client/` from the updated spec.

**After any OpenAPI change:** regenerate before writing frontend code so types and Zod schemas are in sync.

## Forms & State
- Local form state: `useState` + generated Zod schema for validation
- Server state: TanStack Query (`useQuery` / `useMutation`)
- Write-only fields (e.g. passwords, secrets): never pre-populate from server response; use `useRef` guards to prevent form reset on query invalidation

## Design Rules
- Light mode only — no dark mode
- Use existing shadcn components; check `src/components/` before creating new ones
- Framer Motion for transitions

## Dev Commands
```sh
pnpm dev      # start dev server
pnpm build    # production build
pnpm tsc --noEmit  # type check
pnpm generate # regenerate src/client/ from openapi.yaml
```
