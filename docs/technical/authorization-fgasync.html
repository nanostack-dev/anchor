The authorization sync

A generic engine that keeps every Product's OpenFGA store equal to Anchor's tables. A module only says what it owns. The engine does the marking, replaying, sweeping, locking and diffing, once for every module.

1Three layers, one direction

Each layer knows only the one under it. fga and syncer know nothing of Anchor's domain.

NameStored in every mark. Must stay stable; a renamed source's old marks resync the whole Product once.
StaleThe Marker, inside the write's transaction. Pure: reads the event only. An error rolls the write back.
KeysA whole-Product or every-key sync, and the reconcile. The syncer adds keys only a mark still names, such as a deleted Organization.
DesiredEvery sync. Reads the tables now. The syncer drops tuples the model does not define.
StoredEvery sync. Reads only the tuples this key owns, so the diff never touches another module's tuples.

        4Who owns what in Acme's store

        Each source owns a disjoint slice. That is why one module's sync can never delete another's tuples. Click a source.

        5Which marks does an event leave?

        Pick a real Anchor event. The Marker asks every source, and the catalog, which scopes it makes stale.

        One key(source, key)
        The common case: one Organization, one role.
        Every key(source, *)
        A cascade with no events, such as a deleted product user's memberships.
        Whole Product('', '')
        A model change: every source resyncs under the new model.
