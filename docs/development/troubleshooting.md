# Verified development troubleshooting

| Symptom | Verified cause and repair | Verify |
| --- | --- | --- |
| Lint invoked from the wrong directory | Use `./scripts/lint.sh backend`; it resolves `apps/anchor` and the root configuration itself. | Check the reported module, coverage, exit code and full log; a `0 issues` line alone is insufficient. |
| Local UI cannot call shared dev API | Shared dev CORS does not allow the local origin; use the managed disposable app or documented read-only smoke proxy. | Browser guide's health/source checks and affected journey. |
| The app stops at start with configuration issues | Every required setting without a value, and every unknown key or secret in a config file, is listed in one error. Set the missing env variables (see `apps/anchor/cmd/app/CONFIG.md`); a secret comes from its env variable or `*_FILE`, never from a YAML file. | Local `/health` after startup; no secret contents in evidence. |
| Product API key still refuses a newly granted scope | Out-of-band edits do not evict the permission cache. Change scopes through the management API. | Read back key permissions and retry the authorized request; see [cache guide](../api-key-permission-cache.md). |
| Browser UI shows only bootstrap or no scenarios | Playwright retains project/text/status filters. Open its current root URL, clear filters and select bootstrap + chromium. | Compare displayed scenarios with CLI discovery. |
| `go tool nanostack gen` drops the framework settings' descriptions from `cmd/app/config.gen.go`, `CONFIG.md` and `.env.example`, `TestGeneratedFilesAreFresh` fails, or the repository suite cannot find `anchor/migrations` | `GOFLAGS=-trimpath` in `go env` strips source paths, so the generator cannot read the framework's doc comments and `runtime.Caller` paths become module-relative. An empty `GOFLAGS=` falls back to `go env`; override it with any other flag: `GOFLAGS=-mod=readonly go tool nanostack gen`. | `GOFLAGS=-mod=readonly go tool nanostack gen -check` prints nothing. |
| Saving a product event endpoint on `localhost` or a private address answers `400 INVALID_EVENT_ENDPOINT_URL`, or deliveries to a local receiver fail with a non-public address error | Anchor refuses non-public event endpoint addresses when the URL is saved and again when a delivery dials ([product event delivery](../technical/product-event-delivery.md)). | For a local or CI receiver only, set `EVENTS_ALLOW_PRIVATE_ENDPOINTS=true` (`core.events.allow_private_endpoints`). The component, service and contract suites and the e2e runtime already set it. Never set it in a deployed environment. |
| Configuring an SMTP integration on `localhost` or a private address answers `400` (`must be a public address`), or SMTP verification/sends to a local relay fail with `smtp: host address is not public` | Anchor validates outbound SMTP hosts at config validation and again at dial time through `internal/netguard` ([architecture](../technical/architecture.md)). | For a local or CI SMTP relay (such as Mailpit) only, set `INTEGRATION_ALLOW_PRIVATE_HOSTS=true` (`core.integration.allow_private_hosts`). The component, service and contract suites and the e2e runtime already set it. Never set it in a deployed environment. |

Detailed reproduced failures and repairs stay in the [browser troubleshooting guide](../../anchor-ui/e2e/guide/troubleshooting.md) and [CI evidence guide](../../anchor-ui/e2e/guide/ci-failures.md). Add a recipe only after a cause and passing repair are verified; unresolved hypotheses belong in research or the issue.
